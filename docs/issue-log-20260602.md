## 问题 1: LightRAG 的 SiliconFlow API 调用返回 400 Bad Request

### 状态: 已加详细日志，待复现确认根因

### 现象
- 主审计 Pipeline（通过 LangChain ChatOpenAI）调用 SiliconFlow **正常工作**（6 findings 成功产出）
- LightRAG 内部 LLM 调用（通过直接 httpx POST）返回 `400 Bad Request`
- 影响范围：知识图谱索引构建（实体提取阶段）

### 日志证据
```
ERROR: LLM func: Error in decorated function for task 1947301157120_580840.046: Client error '400 Bad Request' for url 'https://api.siliconflow.cn/v1/chat/completions'
ERROR: Failed to extract entities and relationships: C[1/2]: chunk-adaf145e1c4e0aecaa494f9cd2e470bf: HTTPStatusError: Client error '400 Bad Request'...
```

### 已排除的原因
- 模型名 `deepseek-ai/DeepSeek-V3.2`：用户确认正确，连接测试通过（4500ms）
- API Key：主 Pipeline 正常使用
- 基础请求格式：用相同参数（model, messages, temperature, max_tokens）测试 SiliconFlow API 返回 200

### 可能的根因
1. LightRAG 的实体提取 system_prompt 长度（5221 chars）+ user_prompt 导致超出 SiliconFlow 的上下文限制
2. SiliconFlow 对特定模型的 `max_tokens` 值有限制
3. LightRAG 的 prompt 包含特殊字符或格式导致 SiliconFlow 解析失败
4. SiliconFlow 对单次请求的 token 总量有硬性限制

### 已实施的修复
- `agent/tools/lightrag_tool.py:136-141`：添加 400 错误的响应体日志（response body）
- 下次复现时日志将显示 SiliconFlow 返回的具体错误信息

### 待验证
- 重新打包 exe 后复现，查看日志中的 response body
- 如果是 token 限制，需要在 LightRAG 的 LLM 调用中添加 `max_tokens` 动态调整

## 问题 2: KG documents upload 返回 400 Bad Request

### 状态: 已定位根因

### 现象
- `POST /api/kg/documents/upload` 上传 PDF 文件时返回 400

### 根因
PDF 上传走 markitdown 转换 → markitdown 依赖 magika 做内容类型检测 → magika 模型文件未打包到 exe

错误链：
```
kg.py:300 → converter.py:53 → markitdown.convert() → magika model dir not found
→ RuntimeError("文档转换失败") → HTTPException(400)
```

### 日志证据
```
[ERROR] app.services.converter: markitdown conversion failed for GB 41918-2022 生物安全柜.pdf: model dir not found at ...\magika\models\standard_v3_3
```

### 已实施的修复
- `scripts/build.spec`：添加 `'magika'` 到 `collect_all` 列表
- `backend/app/services/converter.py`：添加 `exc_info=True` 和 magika 相关的友好错误提示

### 说明
- 主文档上传（`documents.py`）使用 PyMuPDF 处理 PDF，**不受影响**
- 仅 KG 法规上传（`kg.py`）使用 markitdown，**受影响**

## 问题 3: Magika 模型文件未打包到 PyInstaller 发行版

### 状态: 已修复

### 现象
- exe 中所有依赖 markitdown 的 PDF/DOCX 转换失败
- `markitdown` 内部使用 `magika` 进行内容类型检测
- magika 包含 ~60MB 的 ML 模型文件（`standard_v3_3`）
- PyInstaller 的 `collect_all('markitdown')` 不自动包含 magika 的模型数据

### 根因
`build.spec` 的 `collect_all` 列表缺少 `'magika'` 包。

### 修复
```python
# build.spec — 添加 magika 到 collect_all 列表
'markitdown',       # document converter (pip: markitdown)
'magika',           # markitdown dep: content-type detection with ML models
```

### 影响范围
- KG 法规文档上传（PDF/DOCX → Markdown 转换）
- 不影响主文档上传（使用 PyMuPDF）
