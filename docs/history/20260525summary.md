## 二、LLM 链路修复（8 项）

### 问题根因

```
.env.example: MIMO_API_KEY=your_mimo_api_key_here
    ↓
agent/config.py: api_key = os.getenv("MIMO_API_KEY", "")  → "your_mimo_api_key_here"
    ↓
if not api_key → False（占位符是 truthy 字符串）
    ↓
ChatOpenAI(api_key="your_mimo_api_key_here", ...)
    ↓
HTTP POST → Authorization: Bearer your_mimo_api_key_here → 401 Invalid API Key
```

### Fix 1: 占位符 API Key 检测

在 `get_llm()` 和 `_get_anthropic_llm()` 中添加 `api_key.startswith("your_")` 检查，占位符值直接抛出 `ValueError`。

**文件**: `agent/config.py`

### Fix 2: 后端配置 API 占位符验证

`_apply_setting()` 中添加验证，阻止保存占位符值为 API Key（单条 PUT 路径）。

**文件**: `backend/app/api/config.py`

### Fix 3: Agent Provider 自动降级

新增 `get_llm_with_fallback()` 函数：默认 provider 不可用时，自动尝试其他可用 provider。

```python
def get_llm_with_fallback(model=None, temperature=0.3, max_tokens=4000):
    default = get_default_provider()
    providers = [default] + [p for p in MODEL_ENDPOINTS if p != default]
    for provider in providers:
        try:
            return get_llm(provider, model, temperature, max_tokens)
        except (ValueError, ImportError):
            continue
    raise ValueError("No provider with valid API key available")
```

**文件**: `agent/config.py`

### Fix 4: Agent 节点使用 fallback

3 个 agent 节点（regulation_expert、risk_assessor、report_writer）全部改用 `get_llm_with_fallback()` 替代 `get_llm(provider=None)`。

**文件**: `agent/agents/regulation_expert.py`, `risk_assessor.py`, `report_writer.py`

### Fix 5: 前端 API Key 验证

SettingsPage `handleSave` 中添加占位符检测，保存前拦截 `your_*` 值。

**文件**: `frontend/src/pages/SettingsPage.tsx`

## 三、代码审查发现的 6 个问题（已修复）

### HIGH-1: `clear_llm_cache("anthropic")` 无法清除 Anthropic 缓存

**根因**: Anthropic 缓存 key 是字符串 `"anthropic_default_0.3_4000"`，filter 用 `k[0]` 取首字符 `"a"`，永远不匹配。

**修复**: 统一 Anthropic 缓存 key 为 tuple 格式 `("anthropic", model, temperature, max_tokens)`，与 OpenAI 兼容 providers 一致。同时 `clear_llm_cache()` 兼容 tuple 和 string key。

**文件**: `agent/config.py`

### HIGH-2: `batch_update_config` 绕过占位符验证

**根因**: `POST /batch` 端点不调用 `_apply_setting()`，直接写 DB + env + .env，无 API Key 占位符检查。

**修复**: 在 batch 循环中添加与 `_apply_setting()` 相同的验证。

**文件**: `backend/app/api/config.py`

### MEDIUM-1: `_get_anthropic_llm` 缓存 key 未解析 env model

**根因**: cache key 用 `model or 'default'`，但实际 model 是 `model or model_env or "claude-sonnet-4-20250514"`。

**修复**: 与 HIGH-1 一并修复，cache key 使用 resolved_model。

**文件**: `agent/config.py`

### MEDIUM-2: `lightrag_tool.py` 中 `get_llm` 未走 fallback

**根因**: LightRAG entity extraction 的 Anthropic 分支直接调用 `get_llm("anthropic")`。

**修复**: 改为 `get_llm_with_fallback(temperature=0.3)`。

**文件**: `agent/tools/lightrag_tool.py`

### LOW-1: 前端/后端占位符检测不一致

前端用 `/^your_.*_here$/i`（严格），后端用 `startswith("your_")`（宽松）。

**修复**: 前端改为 `startsWith('your_')`，与后端一致。

**文件**: `frontend/src/pages/SettingsPage.tsx`

### LOW-2: `notify_audit_complete` 带 `task_id` 的路径无测试覆盖

**修复**: 新增 2 个测试用例覆盖 `task_id` 生成 `action_url` 的路径。

**文件**: `backend/tests/test_notification.py`
